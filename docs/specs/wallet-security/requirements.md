## 1. Business Context and Goals

The Oracle SEPS (Secure External Password Store) auto-login wallet is the central security cornerstone of the platform. It allows developers, automation scripts, CI/CD pipelines, and the Dev Hub to connect to databases in a completely passwordless, encrypted manner. The system completely eliminates storing database credentials in plain text files or environment variables, guaranteeing compliance with enterprise Zero-Trust security rules.

### User Roles (Personas):
1. **APEX / Database Developer:** Connects to databases passwordlessly from the command line (`./scripts/sqlcl.sh /@DB_DEV`) or VS Code Oracle extension without needing to know or copy plaintext passwords.
2. **DBA / Security Lead:** Requires that credentials reside strictly encrypted at rest on disk (AES-256) and are decrypted exclusively just-in-time (JIT) in runtime memory.
3. **AI Pair Programmer (Copilot / Antigravity):** Queries credentials from the local wallet via `./scripts/get-password.sh <alias>` without producing plaintext files on the file system.

| Term | Definition | Constraints / Notes |
| :--- | :--- | :--- |
| **SEPS Wallet** | Oracle Secure External Password Store auto-login wallet (`cwallet.sso`). | Do not confuse with TLS/SSL certificate wallets. |
| **cwallet.sso** | Symmetrically obfuscated/encrypted auto-login file used by Oracle clients for passwordless connection. | Resides strictly in `wallet/` directory. |
| **ewallet.p12** | PKCS#12 base encrypted wallet protected by Wallet Master Password. | Used for managing credentials via `mkstore`. |
| **Zero-Trust Rule 5** | Rule strictly prohibiting plaintext credential files (`.env`, `.json`, `.txt`). | Enforced by CI and local unit tests. |
| **Credential Rotation** | Seamless zero-downtime rotation of platform passwords. | `./scripts/internal/rotate-credentials.sh`. |

## 3. Functional Requirements & Acceptance Criteria

### [REQ-SEC-01]: Encrypted Storage at Rest (AES-256 Encryption at Rest)
- **Description:** All database credentials and connection attributes must reside strictly in an encrypted Oracle SEPS Wallet (`cwallet.sso` / `ewallet.p12`) or Podman encrypted secret store.
- **Acceptance Criteria (Given/When/Then):**
  - **Given:** The environment is provisioned via `./scripts/setup-all.sh` or Dev Hub.
  - **When:** The wallet is generated by `create-wallet.sh`.
  - **Then:** Files `cwallet.sso` and `ewallet.p12` are created under `wallet/` with file permissions `0600`.
  - **And:** Zero plaintext password files (`.txt`, `.json`, `.env`) are created on disk.

### [REQ-SEC-02]: Dynamic Just-In-Time In-Memory Retrieval
- **Description:** Applications and CLI helpers may only query credentials dynamically in memory via `./scripts/get-password.sh <alias>`.
- **Acceptance Criteria:**
  - **Given:** A developer or script requires a specific wallet alias credential.
  - **When:** `./scripts/get-password.sh DB_DEV` is executed.
  - **Then:** The script decrypts the credential via `mkstore` directly into process memory and outputs to stdout.
  - **And:** No intermediate cache files or disk traces are created.

### [REQ-SEC-03]: Passwordless SQLcl and VS Code Connectivity
- **Description:** SQLcl CLI and VS Code Oracle extension must connect to the target database without password prompts using SEPS wallet alias (`/@ALIAS`).
- **Acceptance Criteria:**
  - **Given:** The SEPS Wallet is created and `TNS_ADMIN` points to `wallet/`.
  - **When:** `./scripts/sqlcl.sh /@DB_DEV` is invoked.
  - **Then:** Connection succeeds immediately without password prompt (`Connected to: Oracle Database 23ai Free`).

### [REQ-SEC-04]: Zero-Downtime Credential Rotation
- **Description:** Credential rotation must update the database user password first, followed by the wallet entry, without interrupting other active connections.
- **Acceptance Criteria:**
  - **Given:** The system is operational and connections are active.
  - **When:** Credential rotation script is executed.
  - **Then:** The database user and SEPS Wallet entry are updated and the new connection is verified.

## 4. Contradiction & Edge Case Analysis

| Requirement A | Requirement B | Potential Conflict | Solution / Invariant |
| :--- | :--- | :--- | :--- |
| **[REQ-SEC-01] (Encrypted at rest)** | **[REQ-SEC-03] (Passwordless connection)** | How to connect without prompt if file is encrypted? | Oracle SEPS `cwallet.sso` auto-login mechanism decrypts the store in memory using host-bound key. |
| **[REQ-SEC-02] (In-memory retrieval)** | **[REQ-SEC-04] (Rotation)** | In-flight processes might hold stale credentials in memory. | Scripts immediately clear memory variables and verify against database immediately. |
